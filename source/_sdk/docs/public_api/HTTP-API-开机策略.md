# 开机策略

2026-11-05。仅新增 GET/POST /api/boot/config，合计 30 个方法/路径操作，6 路实时流不变。内部 v2 保持原实现。本功能属于现有设备服务，无新增进程、常驻线程或独立系统启动脚本。

## 配置接口

GET 和成功 POST 均返回 HTTP 200：

    {"vio_autostart":false}

POST 接受同一完整对象，仅允许一个布尔字段；不接受字符串、数字、null、重复或未知字段。无需 Idempotency-Key，重复保存相同值不会触发 VIO。GET 返回已保存的下次开机配置，不是当前 VIO 运行状态；状态继续使用 GET /api/vio。POST 200 表示保存成功，不表示算法已启动。

配置位于 /home/VIO/parameters/boot.json。缺文件默认 false；现有文件损坏或无法读取时明确报错，不猜测启用值。写入通过临时文件、fsync、rename 和目录 fsync；写入未确认时应重新 GET 核对。损坏配置可以通过合法 POST 修复。

| 情况 | HTTP / error.code |
| --- | --- |
| 字段或 JSON 非法 | 400 / INVALID_CONFIG |
| HTTP 请求格式不符 | 400 / INVALID_REQUEST |
| 更新上传、安装或维护中保存 | 409 / UPDATE_BUSY |
| 读取失败或配置无效 | 503 / BOOT_CONFIG_INVALID |
| 写入或持久化结果未确认 | 503 / CONFIG_SAVE_FAILED |
| 设备服务不可用 | 沿用 DEVICE_UNAVAILABLE 等本机通信错误 |

error 仅包含 code，没有 message。配置可以在 VIO 或 TF 录制运行中保存，因为只用于下次系统启动，不改变当前任务。

## 每次系统启动只处理一次

1. S97 启动已有设备服务。先初始化更新维护状态，再读取 Linux boot_id。
2. 在 /run/robobaton-neo-device/boot-policy-{boot_id} 独占创建本次开机标记，然后读取配置快照。即使配置为关闭或损坏，也保留标记。
3. 已启用且无维护限制时，在现有 VIO 状态线程内检查就绪条件。启动后留出约 1 秒，最长等待驱动控制端口 30 秒；不新增图像/IMU订阅。
4. VIO 已在运行则跳过；录制/预检已开始或更新占用时也跳过。否则通过已有 VIO 命令队列发起一次 start，沿用标定校验、驱动准备和启动脚本。进程启动失败不自动重试。
5. 网页或实体按键通过同一手动 VIO 入口取消尚未受理的自动启动。已经受理、正在执行的启动仍遵守原启停过渡态规则，不能并行执行第二条命令。

标记不随设备服务退出删除：网页重启、设备服务正常重启或异常退出都不会重新执行本次开机策略。即使在创建标记后、启动前进程崩溃，本次也不补启动；用户可手动操作。它是“至多一次自动尝试”，不是崩溃后保证最终启动。系统重启后新 boot_id 才重新读取配置；修改配置再重启设备服务不会提前生效。

手动停止、VIO 异常退出或启动失败均不自动拉起。不会自动启动 TF 录制、浏览器预览或深度，也不要求 MAVLink 已启用。

开机错误通过已有 GET /api/vio 的 error.code 提示：BOOT_STATE_UNAVAILABLE（无法确认启动周期/创建标记）、BOOT_CONFIG_INVALID、BOOT_UPDATE_BLOCKED、BOOT_TASK_ACTIVE、BOOT_SOURCE_TIMEOUT；实际启动失败沿用 VIO_COMMAND_FAILED。手动接受新命令后按原机制清除命令错误。本次错误不另做跨进程历史账本。

## 网页

实时视图 → 功能控制 → VIO 下方“开机设置”。折叠时保持低强调；展开读取设备。开关与“保存到设备”“刷新设置”独立于现有启动/停止单按钮。明确提示未保存、保存中、已保存且下次开机生效；POST 后独立 GET 一致才确认。响应丢失先 GET，不自动重发 POST。切设备取消旧请求，迟到响应不能覆盖新设备设置；不把设置保存在浏览器替代设备配置。

本机检查入口：tmp/boot-policy/test-host.py、test-browser.cjs。实机结果及限制见本次验证报告；构建和模型测试不代表真实冷启动验收。
