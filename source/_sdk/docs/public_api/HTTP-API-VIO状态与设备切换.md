# ：VIO 状态、设备切换与错误码

2026-11-05。网页和 API 使用同一 HTTP/1.1 服务，默认 80 端口。

## 状态查询

GET /api/vio 返回 HTTP 200，例如：

~~~json
{"state":"running","tracking":"valid","error":null,"warning":null}
~~~

| 字段 | 值与含义 |
|---|---|
| state | stopped、starting、running、stopping、restarting |
| tracking | initializing、valid、invalid 或 null |
| error | null 或仅包含 code 的对象 |
| warning | null 或 {"code":"CALIBRATION_REQUIRED"}，与 error 独立 |

state 的稳定态依据真实 VIO 进程，过渡态来自 HTTP/实体按键共用命令队列。running 只表示进程存在，不保证定位有效。tracking 来自单独的本机遥测观察者：算法 tracking 映射为 valid；initializing/invalid 保持含义。进程不运行、正在启停、源断开、两秒内无新鲜状态或无法识别状态时为 null，不能当作 invalid 或有效零位姿。

该观察者与网页里程计连接独立；没有外部订阅也能查询定位状态。只增加一条本机遥测连接，不读取或消费 VIO 采集队列，不修改前后端算法。正常每 500 ms 检查进程；未知进程状态或观察服务不可用返回 HTTP 503 / VIO_STATE_UNAVAILABLE。网页约每秒查询，命令响应后立即再查；不增加实时状态流和操作历史接口。

错误示例：

~~~json
{"state":"stopped","tracking":null,"error":{"code":"VIO_COMMAND_FAILED"},"warning":null}
~~~

VIO_COMMAND_FAILED 表示启动/停止脚本失败、超时或执行后的实际进程状态与动作不符；VIO_EXITED 表示观察到运行进程在没有启停命令时退出。错误保留到下一条新受理命令或观察到外部启动的新进程；用同一 key 重查已受理命令不会清除错误。bridge 重启后只从真实进程恢复状态，不伪造先前命令记录。

## 命令和里程计

POST /api/vio 的输入及成功响应保持原样：

~~~json
{"action":"start"}
~~~

HTTP 202：

~~~json
{"action":"start","accepted":true}
~~~

受理不代表完成。网页继续使用同一个“启动 VIO / 停止 VIO”按钮；按钮依据 GET 的实际状态，不能根据 POST 受理或里程计到达自行切换。过渡状态和状态未知时禁用启停；重启只在确认运行中时可用。里程计数据结构、时间戳、置信度和轨迹语义不变。

Python：python tools/http-api/client.py http://192.168.11.1 --vio-status。程序调用 Device.vio_status()；Device.command() 仍只表示受理。

## 设备切换

公开运行时统一管理当前地址和连接世代。主动切换设备时：

- 关闭旧里程计、彩色、预览和 IMU 连接，取消旧查询及命令等待。
- 清空旧设备轨迹、实时状态、设备参数和录制状态视图；浏览器已录制的数据保留。
- 地址切换 A→B→A 也使用不同世代，迟到响应不能覆盖当前设备数据。
- 命令重试固定原设备地址和 Idempotency-Key；切换后不向新设备重发旧命令。已送达板端的操作无法通过浏览器取消，返回原设备后应查询实际状态。
- 同设备网络断线重连不重置轨迹；只有主动换设备或实际源帧序号回退才清空轨迹。
- 录制、标定采集、求解或参数发布进行中仍禁止换设备，避免混合两台设备的数据。

只取消旧网络请求，不会停止旧设备的 VIO 或 TF 录制。外部设备地址仍需满足浏览器的跨域/本地网络访问规则，本次没有开放新的 CORS 权限。

## 错误结构迁移

公开失败响应统一为 {"error":{"code":"..."}}，不再返回 message；HTTP 状态保留。错误含义见[错误码表](HTTP-API-错误码.md)，网页自行提供中英文说明，未知错误码原样保留供诊断。MAVLink 原有小写码和异步结果原因码保持原语义。

该变更为实验的明确契约调整，OpenAPI 标注 3.7.0，网页与板端需同步更新。内部 v2 的结构不改；本地计算异常、日志和浏览器录制失败说明仍允许可读文字。

## 验证范围

本机专项检查覆盖无外部订阅时读取状态、命令过渡/失败、异常进程退出、定位数据过期、code-only 响应、跨设备迟到响应与命令重试隔离。板卡结果及网页截图见[本轮验证记录](../HTTP-API-状态与切换验证-2026-11-05.md)。按用户要求未进行多路流占满浏览器连接时的控制排队测试；不将功能短测视为算法精度或长期稳定性验收。

## 默认参数启动

缺少 mono.conf 允许提交启动，POST 仍返回202，不等于定位有效。文件损坏或不可读时不回退；异步启动失败通过 error 报告。运行实例从启动参数快照发送来源元数据，GET 据此给出 CALIBRATION_REQUIRED；警告与 tracking 有效性独立，遥测短暂中断不清除已知警告。停止或尚未收到本次实例元数据时 warning=null，不能凭 null 判断已标定。文件被外部修改不会改变当前运行实例的来源；重启读取新参数。网页同时保留定位状态与默认参数提醒。

系统重启并发约束（2026-11-09）：本模块的业务变更/配置写入在系统重启已受理或重启状态存储异常时返回409 REBOOT_BUSY；先查询[系统状态](HTTP-API-系统.md)，不自动重复变更。普通状态查询保持可用。
