# 实体按键

本增量只接入。HTTP 命令与实体按键共用 VIO/TF 任务准入；按键不是网页模拟点击，关闭浏览器和网络断开后仍可使用。

## 配置接口

GET /api/buttons/config 不带请求体或 query，返回 HTTP 200：

    {
      "short_action": "none",
      "long_action": "record_toggle",
      "long_press_ms": 2000,
      "recording_channels": ["gray", "imu"]
    }

POST /api/buttons/config 完整提交同一结构。Content-Type 必须为 application/json，有唯一 Content-Length，正文 1～511 字节。不接受 chunked、Upgrade、Expect、未知/重复/缺失字段。保存至 /home/VIO/parameters/buttons.json，原子替换并同步文件和目录；回读后返回 200 和生效配置。200 表示配置保存，不触发 VIO 或录制。无需幂等键，相同完整配置可重试；多个页面按保存先后覆盖，不提供 CAS。

| 字段 | 类型及范围 | 含义 |
|---|---|---|
| short_action | string，见下表 | 准备后的第二次短按，在松开时执行 |
| long_action | string，见下表 | 准备后的第二次长按，达到阈值执行一次 |
| long_press_ms | integer，1000/2000/3000/5000 | 长按阈值，毫秒 |
| recording_channels | 非空、去重字符串数组，1～4项 | gray、imu、color、odometry；响应按此顺序排列 |

| 动作 | 行为 |
|---|---|
| none | 消耗本次手势，不执行任务 |
| vio_toggle | 按真实 VIO 进程状态选择 start/stop |
| vio_restart | 仅重启已运行的 VIO；未运行时拒绝 |
| record_toggle | 空闲时开始所选 TF 录制；录制中停止当前任务并保存；预检/保存中拒绝 |

录制用当前板端生效的彩图配置及真实 mono.conf，复用 RBR1 格式和数据管理。按键录制选项独立持久化；网页普通录制选择不会自动覆盖。网页不提供复制或同步实时视图选项；顶部刷新读取整份设备配置，有未保存内容时先提示。点击“保存并生效”后更新设备预设，录制中可编辑和保存但不改变当前任务内容。灰度固定 JPEG Q90；选择 odometry 须先启动 VIO。无需浏览器参与，不启动浏览器录制。

| 返回 | 含义 |
|---|---|
| 400 INVALID_CONFIG | 非法字段/内容/请求头 |
| 408 REQUEST_TIMEOUT | 正文接收未完成 |
| 503 CONFIG_LOAD_FAILED | 配置损坏或不可读取；动作已禁用，可通过重新保存修复 |
| 503 CONFIG_SAVE_FAILED | 保存结果未确认；尤其 rename 后 fsync 失败不可宣称回滚，重新 GET 确认 |
| 503 BUTTON_UNAVAILABLE | 按键线程未启动，拒绝声称配置生效 |

首次无公开配置时，只读兼容旧 button-settings.json：原文件版本 1/2/3 沿用已有迁移规则，录制选择固定 gray+imu；两份均无时使用上例默认值。旧文件不改写。已有文件损坏时禁用，不静默套默认功能。配置保存在设备系统存储，不保存在 TF 卡；程序重启后重载，整机掉电重启实测另计。

## 手势、并发和反馈

1. 先短按松开，只进入准备状态，灯快闪，5 秒内开始下一手势。
2. 第二次短按松开执行短按动作；第二次长按达到阈值执行长按动作一次，继续按住和松手不重复触发。
3. 没准备的长按不执行。启动时按键已按住须先释放；小于40ms手势忽略，驱动另有20ms消抖。
4. 配置保存、驱动断开/重连、采样间隔超过250ms、VIO切换或按键动作处理中会清除准备状态。取消的手势不补执行。
5. 按键独立 IPC 连接只请求 HELLO 和 BUTTON_GET，不申请相机/IMU采集或串口。20ms轮询，断线后最多每秒重连；固定 driver-start 只在板端驱动未就绪时恢复既有服务。
6. HTTP 与按键共用准入和互斥：VIO 命令执行中拒绝新动作/开始录制；预检中拒绝 VIO 与按键录制；录制含里程计时停止/重启 VIO 返回409 RECORDING_REQUIRES_VIO。未选里程计时停止 VIO 保留其他录制和预览。
7. 本地手势不占用 HTTP 的32条幂等键额度，也不会在断线后重放。按键动作和配置保存串行；排队动作如果配置已变化则取消。已经开始的任务不被保存新配置修改。
8. 准备快闪、长按渐亮、初始化/保存慢闪、实际保存完成后成功提示；拒绝短暂错误提示，录制写入/结果持久化失败保留故障提示。VIO有效输出由已有算法灯效消息确认，启动受理不伪装成定位成功。

网页不增加按键事件流、模拟按键或新的任务状态接口。VIO 仍返回202受理，录制仍由 recording/datasets 查询。LED 更新和按键采样独立于可能阻塞的录制目录创建/同步，避免写卡停顿把长按误判为短按。

## 验证方法

本机：bash tmp/test-public-buttons.sh 使用实际HTTP、GPIO IPC客户端和手势状态机，提供合成GPIO与VIO进程；ASan/UBSan覆盖持久化重载、严格字段、兼容读取、损坏修复、短按/长按单次触发、驱动CRC/断线重连、配置变更清除准备、网页并发及TF任务依赖。不会触碰真实GPIO或卡内容。

实机：先保存配置并重新读取、重启桥接验证持久化；再验证网页VIO/录制及共享冲突规则、预览连续性。实体手势与肉眼灯效需要用户操作，不能将合成GPIO测试写成实体按键验收。当前部署及验证结果另见当日验证报告。

系统重启并发约束（2026-11-09）：本模块的业务变更/配置写入在系统重启已受理或重启状态存储异常时返回409 REBOOT_BUSY；先查询[系统状态](HTTP-API-系统.md)，不自动重复变更。普通状态查询保持可用。
