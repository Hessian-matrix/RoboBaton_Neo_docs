#  未压缩灰度通道

2026-11-04。已部署驱动、HTTP 和网页，并接通浏览器动作采集、归档、求解入口及参数保存；实机采集和异常处理已验证，完整动作标定与精度仍待用户上机验证。详见实测与操作步骤（详见产品说明）。

## 请求与生命周期

~~~http
GET /api/stream?channels=gray HTTP/1.1
~~~

GET /api/gray/config 查询当前档位；POST /api/gray/config 使用 application/json 正文，例如 {"fps":30}。返回示例：

~~~json
{"fps":30,"supported_fps":[5,30],"available_fps":[5,30]}
~~~

fps 是配置值，驱动重启恢复 5；supported_fps 是全部档位，available_fps 是此刻新订阅可选的档位。同一灰度通道被占用时返回空数组。配置不会占用通道，查询不保证稍后的订阅成功。只允许 5 或 30，非法值 400 INVALID_CONFIG；已有订阅或新档与当前其他业务冲突时不能变更档位（409 CONFIG_CONFLICT），重复设置同值幂等。冲突后重新查询，不自动重试或改动已有业务。

每个图像通道最多一个 HTTP 客户端，第二个请求返回 409，例如 {"error":{"code":"IMAGE_CONFLICT"}}。原灰 5 fps 可以与其他图像并行；有 VIO 时，同时输出的全彩至多 5 fps。原灰 30 fps 与全分辨率彩色、gray_jpeg、任何含图像的 TF 录制互斥；无论 VIO 是否开启，均允许同时接收一路彩色预览；depth 只在 VIO 关闭时允许与原灰 30 fps 并行。这是允许订阅的档位，不保证实收帧率。IMU 与位姿仍可并行。无论先订阅、先开始 TF 录制或先启动 VIO，后到且不兼容的操作被拒，已有操作保持。标定采集前网页内部设置 5 fps。实时页“灰度图像输出 → 设置与接口”只查询配置，5 和 30 两档都显示，不可用档位置灰。窗口可见时会复查，通道释放后恢复可选。点“应用参数”才写配置，点“开启取流”才订阅；关闭窗口释放本页的订阅。

流接口每连接一个通道；IMU 使用独立连接。图像按需采集，关闭只释放自身引用。订阅不启动 VIO。HTTP 200 后先解 chunk，再解 RBH1，TCP read、HTTP chunk 与图像帧边界均不相同。

未开始响应前，服务不可用为503 GRAY_UNAVAILABLE，内存不足为503 OUT_OF_MEMORY；首次最多等待8秒，未取得新鲜图像为503 GRAY_NOT_READY。已开始200响应后，源故障、3秒无新图、采集session/图像源epoch变化、序号或有效时间倒退均结束连接。客户端重新GET，重新读取元数据，不拼接半帧、不补历史；不能仅凭重连判断IMU与图像跨重启连续。

## 首条元数据

RBH1 channel=0，format=1，JSON：

~~~json
{
  "type": "metadata",
  "connection_id": "gray",
  "stream": {
    "source": {"type": "live"},
    "channels": [{"id": 5, "name": "gray", "format": 8}]
  },
  "config": {
    "encoding": "raw",
    "pixel_format": "mono8",
    "width": 544,
    "height": 640,
    "stride": 544,
    "fps": 5
  }
}
~~~

connection_id 为通道标签，不作为设备身份或采集epoch。尺寸/stride单位为像素/字节，fps为名义输出频率。过载允许跳帧；不能用5fps生成假时间戳。

## 每帧二进制

RBH1 channel=5，format=8，每个业务消息为：

| 字节偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | 小端uint32，UTF-8 JSON字节数N |
| 4 | N | 下列帧头JSON，1≤N≤252 |
| 4+N | 348160 | 544×640灰度像素，每像素一个uint8，逐行连续、无行填充 |

~~~json
{"header":{"seq":"1201","stamp":{"sec":123,"nanosec":456789000}}}
~~~

- seq：真实采集帧序号，uint64十进制字符串；JS使用BigInt。不是5Hz重新编号的计数，也不是RBH1传输序号。在稳定 60 Hz 源上，5 fps 档相邻序号通常相差 12，30 fps 档通常相差 2；在 30 Hz 源上，30 fps 档逐帧输出。跳号不自动等于丢帧；时钟抖动、竞争、过载可能改变间隔。
- stamp：与IMU同域的CLOCK_MONOTONIC_RAW曝光中点，sec为秒，nanosec为0..999999999。纳秒总值不超过INT64_MAX。未可靠关联曝光时为null，标定消费者应排除该帧，不用网络接收时间补值。原始流不预加标定时间偏移。
- 像素就是VIO采集输入的Y8平面，未经JPEG/H26x压缩，也不是Sensor Bayer RAW。不叠加特征点、不旋转；与544×640标定网格一致。
- raw每帧独立，不需要PTS、random_access或编码器参数集。灰度图内存使用stride544；不泄露硬件行填充/物理地址。

RBH1仍为40字节小端头、版本1；单片最多65536字节，灰度业务消息最大348416字节。按同一传输序号和连续offset重组，完整消息后才交付像素。具体RBH1定义见[通用协议](HTTP-API.md)，具体schema见[OpenAPI](http-api.openapi.json)。format8只用于网络灰度 mono8；TF 录制的灰度仍采用 JPEG。

## 资源与数据优先级

灰度按所选 5 fps 或 30 fps 输出；不能根据输出帧率推断采集频率或端到端延迟。

灰度网络输出为尽力传输，可能跳号或断线，不保证无丢帧。一个通道只允许一个外部客户端；超时或断开仅释放该连接，不停止 VIO 或录制。

单路纯像素带宽：5 fps 为 1,740,800 B/s（约 13.93 Mbit/s），30 fps 为 10,444,800 B/s（约 83.56 Mbit/s）；两者均不含传输头。

## 公开网页标定流程

- 确认屏幕标定板尺寸后连接gray、imu及独立彩色preview，数据就绪后进入动作采集。只支持DS；兼容内部动作诊断的本地模式键仍为gray4，标定实际使用原灰 5 fps。
- 网页创建本地采集会话，不自动启停VIO，不依赖实体按键。建议在正式标定前手动停止VIO。
- 保存原始曝光时间和IMU逐样本时间、源序号；不改成网络到达时间，不提前应用相机/IMU时间偏移。两个连接可先后到达，最多等待5张图，确保所存图像前后至少各100ms的IMU覆盖。
- 灰度在浏览器内无损保存为PNG，IMU为EuRoC CSV；capture.json记录传输来源，calibration-parameters.json保存准备本次采集时读取的标定参数快照，不创建第二份板端生效参数。硬件同步误差未知时syncErrorNs=null，不假报零。
- 断线、IMU缺号或超过15ms间隔、无效曝光、图像倒退或超过400ms间隔会中断，保留未完成数据供下载，禁止作为有效数据求解。不能自动重连续录。正常结束等待最后图像的IMU尾部收齐。
- 会话仅存页面内存，用户主动下载ZIP；有效ZIP可重新打开求解，未完成ZIP会被拒绝求解。单会话保守计数上限256MiB或15分钟，达到上限按中断保存；不等同浏览器总内存上限。页面关闭前应下载文件。
- 动作识别仍采用已确认的固定出厂参考内外参。当前设备参数仅作为会话参数快照和IMU噪声来源；彩色预览不参与标定计算。保存结果沿用POST /api/calibration/parameters，VIO运行中返回409，不代用户停算法。
